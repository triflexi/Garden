# Листва

Личный трекер полива комнатных растений. Русский интерфейс, светлая и тёмная темы, адаптивная коллекция с иллюстрациями, история поливов и статистика.

**Стек:** React + Vite + TypeScript, Coss UI / Base UI, Aceternity Liquid Glass, Tailwind CSS 4, NestJS, Prisma, PostgreSQL. Мониторинг: VictoriaMetrics + Grafana. Доступ к приложению — **HTTP по IP, без домена и сертификатов**.

## Быстрый запуск в Docker

Нужны Docker Engine / Docker Desktop с Linux-контейнерами и Docker Compose ≥ 2.24.4. На Linux VPS рекомендуется минимум 2 vCPU и 4 ГБ RAM для приложения вместе с мониторингом.

```bash
cp .env.example .env
# Замените DB_PASSWORD и GRAFANA_PASSWORD в .env.
docker compose up -d --build
```

В PowerShell скопировать файл можно командой `Copy-Item .env.example .env`.

- Приложение: http://localhost:8080
- OpenAPI: http://localhost:8080/api/docs
- Grafana: http://localhost:3001, пользователь `admin`, пароль из `.env`.

Создайте аккаунт в интерфейсе. Демонстрационные пользователи и растения автоматически не добавляются. Миграции выполняются отдельным контейнером до запуска API.

Для VPS укажите `HTTP_PORT=80` и `PUBLIC_ORIGIN=http://ВАШ_IP`. Снаружи доступны только HTTP-приложение и SSH. PostgreSQL, API, VictoriaMetrics и экспортёры остаются внутри Docker-сети. Grafana слушает только localhost; для доступа с компьютера используйте:

```bash
ssh -L 3001:127.0.0.1:3001 USER@YOUR_IP
```

После этого откройте http://localhost:3001. Экспортёры ресурсов рассчитаны на Linux VPS; на Docker Desktop они показывают ресурсы Linux VM Docker, а не Windows.

Остановка без удаления данных: `docker compose down`. Данные PostgreSQL, метрик и Grafana сохраняются в именованных volumes. `docker compose down -v` удаляет эти данные; эта команда используется только для очистки тестового окружения.

## Разработка

Нужны Node.js 24 и npm. В `.env` задайте `DATABASE_URL` для локального PostgreSQL. Для БД в Docker:

```bash
docker compose -f compose.dev.yaml up -d --wait
npm ci
npm run db:deploy
npm run dev
```

Dev-БД доступна на `localhost:15432`; порт можно изменить через `DB_PORT` вместе с `DATABASE_URL`. Скрипт `dev` запускает API на порту 3000 и Vite на http://localhost:5173, загружает корневой `.env` и задаёт отдельный dev-origin. Vite проксирует `/api`; CORS и хранение токенов в localStorage не требуются. На Windows используйте `npm.cmd`, если PowerShell перехватывает сломанный глобальный `npm.ps1`.

```bash
npm run typecheck
npm test
npm run build
bash tests/ops/deploy.test.sh
npx playwright install chromium
npm run test:e2e
```

API-тесты с PostgreSQL запускаются, когда `DATABASE_URL` передан в окружении процесса. Они создают аккаунты с уникальным префиксом и удаляют только свои данные. Без этой переменной интеграционные тесты явно пропускаются; календарные и фронтенд-тесты выполняются всегда.

Для проверки полного контейнерного запуска:

```bash
E2E_BASE_URL=http://localhost:8080 npm run test:e2e
bash scripts/smoke.sh
```

`smoke.sh` проверяет цели мониторинга, дашборд, резервную копию и восстановление во временную БД, а затем поочерёдно останавливает и возвращает БД и API для проверки health monitoring. Запускайте его в тестовом окружении: он кратковременно останавливает БД и API.

UI-компоненты устанавливаются через официальные реестры:

```bash
npx shadcn@latest init @coss/style --cwd apps/web
npx shadcn@latest add @aceternity/liquid-glass --cwd apps/web
```

Исходники компонентов принадлежат проекту и находятся в `apps/web/src/components/ui`. Перед повторной инициализацией учитывайте, что CLI может перезаписать стили компонентов. Liquid Glass использует преломление в Chromium и матовое стекло в остальных браузерах.

## Как устроен полив

Для растения задаётся интервал от 1 до 365 дней. Следующий полив считается от последнего фактического полива в календарных днях часового пояса аккаунта. Если последний полив неизвестен, растение требует полива со дня добавления. При изменении интервала и отмене записи дата пересчитывается.

Историческую дату последнего полива можно задать при добавлении растения. Будущие и несуществующие даты отклоняются. Запись полива с тем же `requestId` не дублируется. В истории можно отменить ошибочный полив. Операции с растениями, поливами и статистикой всегда ограничены владельцем.

Аккаунт: email и пароль минимум 8 символов. Подтверждения, восстановления и внешних входов нет. Пароли хешируются Argon2id. Случайный токен сессии передаётся в HttpOnly / SameSite=Lax cookie, его хеш хранится в PostgreSQL. Сессия действует 7 дней, выход отзывает её. Для выбранного HTTP cookie имеет `Secure=false`.

## Мониторинг

VictoriaMetrics самостоятельно собирает метрики каждые 15 секунд, хранит их 30 дней и служит источником данных Grafana. Дашборд «Листва · приложение и сервер» добавляется автоматически.

- node-exporter: CPU, использованная и доступная RAM, свободное и занятое место VPS.
- cAdvisor: CPU, память, лимиты и оставшаяся память контейнеров.
- blackbox-exporter: HTTP-доступность веб-сервера и готовность API / PostgreSQL.
- API: длительность и количество запросов, ошибки, состояние БД и просмотры страниц.

Liveness: `/api/health/live`. Readiness: `/api/health/ready` с проверкой БД. `/metrics` доступен только напрямую во внутренней сети; Nginx не публикует его.

Просмотр — открытие, обновление или переход на экран. Запросы API, повторные React-рендеры и health checks не считаются. Итоги просмотров сохраняются в PostgreSQL, поэтому перезапуск API не обнуляет счётчик. Метрика `app_page_views_total{route="..."}` содержит только имена экранов, без email и идентификаторов растений. В Grafana используется `sum(increase(app_page_views_total[1h]))` — мониторинговая оценка количества просмотров за час на основе 15-секундных измерений, а не журнал индивидуальных посещений.

## VPS и GitHub Actions

1. Установите Docker Engine и Compose plugin на Ubuntu 24.04 LTS по официальной инструкции Docker. Откройте TCP 80 и SSH; остальные сервисы наружу не публикуйте.
2. Создайте каталог `/opt/listva`, принадлежащий пользователю деплоя. Скопируйте туда репозиторий и выполните `bash scripts/bootstrap.sh YOUR_PUBLIC_IP`. Скрипт создаёт `.env` со случайными паролями и HTTP-настройками, не перезаписывая существующий файл.
3. Для закрытых образов один раз выполните на VPS `docker login ghcr.io` с токеном только на чтение Packages. У пользователя деплоя должен быть доступ к Docker.
4. В GitHub создайте environment `production`. Добавьте secrets: `DEPLOY_HOST`, `DEPLOY_USER`, `SSH_PRIVATE_KEY`, `SSH_KNOWN_HOSTS`. В `SSH_KNOWN_HOSTS` запишите проверенный ключ VPS. Variable `DEPLOY_PATH` необязательна, по умолчанию `/opt/listva`.
5. После push в `main` workflow CI проверяет типы, unit/integration-тесты, сборки, контейнерные E2E, мониторинг и восстановление резервной копии. Только после успешного CI workflow Build and deploy публикует образы в GHCR и обновляет VPS по SSH.

Образы получают теги commit SHA, а деплой использует их неизменяемые digest SHA-256. Деплои выполняются последовательно. Перед обновлением существующей установки сохраняется резервная копия PostgreSQL, включая обновление контейнера БД. Миграция выполняется до обновления API; при её ошибке старое приложение продолжает работать. Новые образы сохраняются как рабочие только после успешного health check. При провале проверки возвращаются предыдущие образы приложения. БД автоматически назад не мигрируется: последующие миграции должны оставаться совместимыми с предыдущей версией API.

Для ручного запуска тех же образов:

```bash
API_IMAGE=ghcr.io/OWNER/REPOSITORY-api@sha256:API_DIGEST \
WEB_IMAGE=ghcr.io/OWNER/REPOSITORY-web@sha256:WEB_DIGEST \
bash scripts/deploy.sh
```

Сам репозиторий и VPS не создаются workflow автоматически. Секреты не входят в исходники или Docker-образы.

## Резервное копирование

```bash
bash scripts/backup.sh
bash scripts/restore.sh backups/FILE.dump --confirm-replace-database
```

Копии находятся в `backups/`, имеют закрытые права и не попадают в Git. Перед восстановлением создаётся ещё одна копия текущей БД, API останавливается, восстановление выполняется транзакционно. Если оно не удалось, API остаётся остановлен и выводится ошибка. Для независимого хранения копируйте архивы за пределы VPS; локальный volume не заменяет резервную копию.

## Структура

`apps/web` — интерфейс; `apps/api` — API и Prisma-миграции; `infra` — Nginx и мониторинг; `scripts` — разработка и эксплуатация; `.github/workflows` — CI/CD; `tests/e2e` — сценарии пользователя.
